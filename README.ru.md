## Что это

`winvestour-bot` — небольшой торговый движок, который вы запускаете **на своих собственных аккаунтах**: он читает спотовый рынок Binance **вашим** API-ключом, принимает решения по правилам, которые раз в день пишет модель Claude, и может размещать реальные ордера на вашем счёте. Каждая установка — собственная копия: база данных, ключ Binance и API-ключ Claude остаются в вашем хостинге, и ничто в этой копии не обращается к сопровождающему. Он для одного человека, который хочет запустить такой движок для себя, сначала прочитать код и начать с небольшой суммы.

**Содержание:** [Что понадобится](#что-понадобится) · [Установка с помощью ИИ-ассистента](#установка-с-помощью-ии-ассистента) · [Установка](#установка) · [Первое использование](#первое-использование) · [Ежемесячная стоимость работы](#ежемесячная-стоимость-работы) · [FAQ / устранение неполадок](#faq--устранение-неполадок) · [Участие](CONTRIBUTING.md)

## Что понадобится

- **Аккаунт Vercel на тарифе Pro.** Движок приводится в действие запланированной задачей, которая выполняется **каждую минуту** (`vercel.json`). Бесплатный тариф Hobby у Vercel разрешает запланированную задачу не чаще **одного раза в день**, а документация говорит, что более частое расписание *не проходит развёртывание* — то есть на Hobby развёртывание не выходит в эксплуатацию. Прочитайте цены и условия Vercel, прежде чем выбирать.
- **Аккаунт Neon** (PostgreSQL). Бесплатного тарифа хватает для таблиц; в разделе о стоимости ниже сказано, что было измерено.
- **Аккаунт Upstash** (Redis). Квоты бесплатного тарифа хватает на одну открытую позицию одновременно.
- **API-ключ Anthropic.** Модель, пишущая правила («Мозг»), по умолчанию вызывается раз в день; свежая установка рождается с **пустым** лимитом расходов, и пока он пуст, Мозг **не** вызывается.
- **API-ключ Binance типа Ed25519, созданный без права на вывод средств.** Ключ с включённым выводом или универсальным переводом отклоняется и никогда не сохраняется.
- **Node.js и npm** на вашем компьютере для команд установки, и в общей сложности около **одного часа**.

Эта копия не несёт ничего от сопровождающего: код не читает доменное имя, в контракте окружения нет имени пакета Android и отпечатка подписи, и три переменные Firebase необязательного дополнения push-уведомлений рождаются пустыми, поэтому уведомления выключены. Всё ниже рождается пустым, и вы заполняете это своими значениями.

| Переменная окружения | Откуда берётся значение |
|---|---|
| `DATABASE_URL` · `DIRECT_URL` | Neon → ваш проект → строки подключения (с пулом · прямая) |
| `UPSTASH_REDIS_REST_URL` · `UPSTASH_REDIS_REST_TOKEN` | Upstash → ваша база → REST API. Если вы добавляете Upstash через Vercel Marketplace, он задаёт имена `KV_REST_API_URL` и `KV_REST_API_TOKEN`; приложение читает и их. |
| `ANTHROPIC_API_KEY` | Anthropic → API-ключи (начинается с `sk-ant-`) |
| `OWNER_PASSWORD_HASH` · `OWNER_TOTP_SECRET` · `SESSION_SECRET` | файл, записанный шагом установки 4 |
| `STOP_KEY_HASH` | файл, записанный шагом установки 5 |
| `ENCRYPTION_MASTER_KEY` | файл, записанный шагом установки 6 |
| `ENCRYPTION_KEY_VERSION` | `1` при свежей установке (повышается только при ротации мастер-ключа, шаг 15) |
| `ENCRYPTION_MASTER_KEY_PREVIOUS` | оставьте пустым; используется только во время ротации мастер-ключа |
| `ENGINE_MODE` | `CHEAP` (один тик в минуту из запланированной задачи; единственный режим, который описывает этот README) |

API-ключ Binance — **не** переменная окружения: он передаётся через приложение после установки и хранится в вашей базе данных, зашифрованный вашим мастер-ключом (см. «Первое использование»).

## Установка

Каждый из 15 шагов ниже проходится перед каждым выпуском в чистой копии этого репозитория — шаги 1–14 — автоматическая проверка установки, шаг 15 — проверка ротации ключа. Шаг, который так не проходится, здесь не записан.

1. Заведите нужные аккаунты (в сумме около 30 минут): аккаунт **Neon** (база данных PostgreSQL), аккаунт **Upstash** (Redis), аккаунт **Vercel** на **тарифе Pro** (приложение запускает запланированную задачу каждую минуту; на бесплатном тарифе Hobby развёртывание не проходит — см. «Что понадобится»), API-ключ **Anthropic** и API-ключ **Binance**, созданный **без права на вывод средств**.

Ожидаемый результат: вы можете войти во все пять сервисов, а в правах вашего API-ключа Binance нет вывода средств.

2. Скачайте код на свой компьютер: на странице этого репозитория выберите **Code → Download ZIP** (или клонируйте его своим git-клиентом), распакуйте и откройте терминал в этой папке.

Ожидаемый результат: в папке есть `package.json` и `.env.example`.

3. Установите зависимости из lock-файла копии:

```sh
npm ci
```

Ожидаемый результат: команда завершается без ошибки, появляется папка `node_modules`.

4. Сгенерируйте пароль владельца, секрет TOTP и секрет сессии. Значения не выводятся на экран, только пути к файлам и короткие отпечатки; значения записываются в папку вне репозитория (по умолчанию `winvestour-backup` в вашей домашней папке, `-- --dir <папка>` для другого места):

```sh
npm run owner:credentials
```

Ожидаемый результат: в папке появились `owner-credentials.txt`, `vercel-env-owner.txt`; в первом файле ваш пароль и ключ настройки TOTP для приложения-аутентификатора, во втором — три строки `NAME=value` для шага 9. На экран не выводится ни одно значение — только пути к файлам и короткие отпечатки.

5. Сгенерируйте ключ остановки (записывается в ту же папку, не выводится на экран):

```sh
npm run stop:credential
```

Ожидаемый результат: в папке появляются `stop-key.txt`, `vercel-env-STOP_KEY_HASH.txt`; в первом файле сырой ключ остановки, который вы будете вводить на экране остановки, во втором — его хеш для шага 9.

6. Сгенерируйте мастер-ключ, которым шифруются ваши биржевые ключи (записывается в ту же папку, не выводится на экран). Если этот ключ потерян, зашифрованные строки больше никогда не откроются; храните вторую копию в менеджере паролей:

```sh
npm run key:encryption-master
```

Ожидаемый результат: в папке появляются `encryption-master-key.txt`, `vercel-env-ENCRYPTION_MASTER_KEY.txt`.

7. Сгенерируйте пару ключей Ed25519 для API-ключа Binance (записывается в ту же папку; закрытый ключ не выводится на экран):

```sh
npm run key:generate
```

Ожидаемый результат: в папке появляются `binance-private-key.pem`, `binance-public-key.pem`. На Binance выберите Profile → API Management → Create API → **Self-generated** и вставьте содержимое второго файла (открытый ключ); первый файл (закрытый ключ) вы позже вставите в панель («Первое использование»).

8. Создайте пустую базу данных PostgreSQL: в Neon создайте проект и скопируйте две его строки подключения — пулированная становится `DATABASE_URL`, прямая (без пула) — `DIRECT_URL`. Выберите регион **AWS Asia Pacific (Singapore)** (`aws-ap-southeast-1`): функции приложения работают в Токио (`hnd1`, см. `vercel.json`), а у Neon нет региона в Токио; ближайший — Сингапур (список регионов Neon, прочитан 2026-09-26).

Ожидаемый результат: две строки, начинающиеся с `postgresql://`; в базе данных пока нет таблиц.

9. Задайте значение каждому имени из `.env.example` — кроме `ENCRYPTION_MASTER_KEY_PREVIOUS`, которое остаётся пустым (используется только при ротации мастер-ключа), и кроме трёх необязательных `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY`, которые тоже остаются пустыми, если вы не подключаете собственный Firebase для push-уведомлений (см. соответствующий раздел ниже). Откуда берётся каждое значение — в таблице раздела «Что понадобится»; `OWNER_PASSWORD_HASH`, `OWNER_TOTP_SECRET`, `SESSION_SECRET`, `STOP_KEY_HASH`, `ENCRYPTION_MASTER_KEY` берутся из файлов шагов 4–6. Для развёртывания введите их в Vercel в **Settings → Environment Variables**; для локального запуска запишите те же имена в файл `.env` рядом с `package.json` (git игнорирует этот файл). Значения никогда не попадают в репозиторий.

Ожидаемый результат: у каждого имени из `.env.example`, кроме `ENCRYPTION_MASTER_KEY_PREVIOUS` и трёх необязательных имён `FIREBASE_*`, есть значение. Если обязательное имя отсутствует, приложение останавливается при запуске и называет недостающую переменную.

10. Создайте таблицы базы данных. Выполните это один раз со своего компьютера при заданном `DIRECT_URL` (в `.env` или в терминале); Vercel повторяет ту же команду при каждом развёртывании, это безвредно:

```sh
npx prisma migrate deploy
```

Ожидаемый результат: вывод заканчивается строкой `All migrations have been successfully applied.` Применяется единственная миграция с именем `0_baslangic`; каждая таблица настроек начинается с одной строки; настройки риска пусты и выключены.

11. Проверьте, что код собирается на вашем компьютере (рекомендуется перед развёртыванием):

```sh
npm run build
```

Ожидаемый результат: команда завершается списком маршрутов без ошибок; появляется папка `.next`.

12. Запустите локально. Когда приложение поднимется, откройте в браузере `http://localhost:3000/api/health`:

```sh
npm start
```

Ожидаемый результат: страница показывает `{"ok":true,"service":"engine",...}`, а `http://localhost:3000/panel` открывается и сообщает, что панели нужна сессия. При запуске проверяется контракт окружения: если обязательное имя отсутствует или некорректно, сервер не поднимается, а ошибка называет недостающую переменную, но никогда её значение. Остановите сервер через Ctrl+C. Запуск бота на своём компьютере пока не поддерживается: движок запускается через Vercel Cron. Локальный запуск служит только для проверки установки.

13. Разверните на Vercel: отправьте свою копию в собственный аккаунт GitHub, затем в Vercel выберите **Add New → Project → Import** для этого репозитория, оставьте пресет фреймворка **Next.js**, добавьте переменные окружения из шага 9 и нажмите **Deploy**. Vercel выполняет скрипт `vercel-build`: сначала он отклоняет любую миграцию, которая удалила бы данные, затем создаёт таблицы и собирает.

Ожидаемый результат: развёртывание достигает состояния **Ready**, а `https://<ваш-проект>.vercel.app/api/health` возвращает `{"ok":true,...}`. На тарифе Hobby развёртывание вместо этого падает с сообщением, что cron-выражения, срабатывающие чаще одного раза в день, не разрешены.

14. Откройте панель по адресу `/panel` на вашем домене и экран остановки по адресу `/durdur`.

Ожидаемый результат: обе страницы открываются на языке вашего браузера, если это один из семи языков этого README, иначе на английском; переключить язык можно в меню языка вверху страницы. Панель сообщает, что ей нужна сессия; экран остановки открывается без сессии и запрашивает ключ остановки. Продолжайте с раздела «Первое использование».

15. НЕОБЯЗАТЕЛЬНО, НЕ ЧАСТЬ УСТАНОВКИ — РОТАЦИЯ МАСТЕР-КЛЮЧА. Если ваш мастер-ключ утёк или вы хотите его сменить: отложите старый файл резервной копии, снова выполните шаг 6, чтобы сгенерировать НОВЫЙ ключ, передайте новый как `ENCRYPTION_MASTER_KEY`, старый как `ENCRYPTION_MASTER_KEY_PREVIOUS`, и увеличьте `ENCRYPTION_KEY_VERSION` на единицу. По умолчанию это ПРОБНЫЙ ЗАПУСК: ничего не записывается, измеряется только возможность расшифровки; добавьте `-- --write`, чтобы записать на самом деле:

```sh
npm run rotate:encryption-key
```

Результат: каждая строка расшифровывается старым ключом и заново упаковывается новым в отдельной транзакции, а её версия повышается; новый конверт проверяется новым ключом ДО того, как что-либо записывается. Когда на старой версии не остаётся ни одной строки, `ENCRYPTION_MASTER_KEY_PREVIOUS` можно удалить. Значение ключа никогда не выводится.

### 1. Вход (пароль владельца, затем одноразовый код для каждого чувствительного действия)

Откройте `https://<ваш-проект>.vercel.app/panel`. Без сессии панель показывает одно поле **Пароль**<!-- ad:login.password --> и кнопку **Войти**<!-- ad:login.submit -->: введите пароль из `owner-credentials.txt` (шаг установки 4) и нажмите кнопку — та же страница откроет панель. Сессия длится **8 часов**. Неверный пароль показывает "Неверный пароль, попробуйте ещё раз."<!-- ad:login.wrong -->. После **5** неверных попыток вход и все чувствительные действия блокируются на **15 минут** ("Слишком много неверных попыток: вход заблокирован. Попробуйте снова не позднее чем через 15 мин."<!-- ad:login.locked|minutes=15 -->); экран остановки не блокируется никогда. **Выйти**<!-- ad:panel.signOut --> — вверху панели. Один раз добавьте ключ настройки TOTP из `owner-credentials.txt` в приложение-аутентификатор.

### 2. Вкладка **Статус**<!-- ad:tabs.status -->: состояние движка и "Перед запуском"<!-- ad:engine.beforeYouStart -->

Карточка **СОСТОЯНИЕ ДВИЖКА**<!-- ad:engine.label --> вверху показывает одно из четырёх состояний, прочитанных с сервера: **Работает**<!-- ad:engine.state.RUNNING.name --> · **Остановлен**<!-- ad:engine.state.STOPPED.name --> (остановлен вами или правилом защиты) · **Не запущен**<!-- ad:engine.state.NO_PERMIT.name --> (не запускался, или истекло разрешение на работу) · **Неизвестно**<!-- ad:engine.state.UNKNOWN.name --> (состояние не прочитано; предлагается **СТОП**<!-- ad:engine.stop -->, но не **ЗАПУСК**<!-- ad:engine.start -->). Ниже **Перед запуском**<!-- ad:engine.beforeYouStart --> перечисляет, что нужно движку: **Ключ Binance · Интервал тиков · Лимит расходов · Стоимость инфраструктуры · Доля одной позиции · Общая экспозиция**<!-- ad:prereq.names.key,prereq.names.tick,prereq.names.cap,prereq.names.infra,prereq.names.single,prereq.names.total --> — каждая строка ✓ (готово), ✗ (нет) или ? (не прочитано) — и две информационные строки: **Переключатель входов**<!-- ad:prereq.names.entry --> и **Капитал**<!-- ad:prereq.names.capital -->. Пока хоть одна строка ✗ или ?, кнопка **ЗАПУСК**<!-- ad:engine.start --> скрыта, а ссылка "Сначала: …"<!-- ad:prereq.keyFix|pre --> ведёт к нужной настройке. Предупреждения (например, отсутствующий защитный ордер) появляются под "Сначала посмотрите сюда"<!-- ad:status.alertsHeading -->, а "Кратко"<!-- ad:status.summaryHeading --> показывает последний прогон движка, открытые позиции и комиссию, уплаченную за период.

![Вкладка Статус — mobile 390](images/panel-status-mobile-390.png) ![Вкладка Статус — desktop 1280](images/panel-status-desktop-1280.png)

### 3. Заполните вкладку **Настройки**<!-- ad:tabs.settings -->

![Вкладка Настройки с готовыми профилями — mobile 390](images/settings-profiles-mobile-390.png) ![Вкладка Настройки с готовыми профилями — desktop 1280](images/settings-profiles-desktop-1280.png)

- **API-ключ Binance**<!-- ad:key.heading -->: сначала создайте ключ. Сгенерируйте пару Ed25519 командой `npm run key:generate` (шаг установки 7) или собственным генератором ключей Binance; на Binance откройте Profile → API Management → Create API → **Self-generated**, вставьте открытый ключ, дайте имя и пройдите двухфакторную проверку. Права: чтение **вкл.** (ключ без чтения отклоняется), спотовая торговля **вкл.**, чтобы движок мог размещать ордера, фьючерсы — только если вы ими пользуетесь, вывод средств и универсальный перевод **выкл.** В панели откройте **Настройки → API-ключ Binance → Добавить ключ (нужен одноразовый код)**<!-- ad:tabs.settings>key.heading>key.add -->, заполните **Имя**<!-- ad:key.fieldName|head -->, **API-ключ**<!-- ad:key.fieldApiKey|head -->, **Закрытый ключ**<!-- ad:key.fieldPrivate|head --> (всё содержимое `binance-private-key.pem`; поле остаётся скрытым) и одноразовый код и нажмите **Проверить и сохранить ключ**<!-- ad:key.submit -->. Приложение проверяет права на Binance, прежде чем что-либо сохранить; ключ с включённым выводом или универсальным переводом отклоняется ("Ключ ОТКЛОНЁН: …"<!-- ad:key.withdrawals|pre -->) и нигде не сохраняется. Принятый ключ хранится зашифрованным вашим мастер-ключом и больше никогда не показывается. С новым ключом движок использует самый новый; старые ключи удаляйте на Binance сами.
- **Интервал тиков — как часто работает движок**<!-- ad:tick.heading -->: рождается **пустым**; без него движок не запускается. Откройте **Изменить (реже — без кода; чаще — нужен код)**<!-- ad:tick.change --> и выберите одну из кнопок: **каждые 1, 2 или 3 минуты**. Изменение вступает в силу **не позднее чем через 20 минут** или при следующем запуске движка.
- **Месячный лимит расходов**<!-- ad:cap.heading -->: рождается **пустым**; пока он пуст, движок решений (Claude) **не вызывается** вовсе. Чтобы он работал, откройте **Изменить лимит (…)**<!-- ad:cap.change|paren -->, отметьте **Месячный общий лимит расходов**<!-- ad:cap.fieldTotal --> и **Месячная стоимость инфраструктуры (сумма ваших собственных счетов Neon, Vercel и Upstash)**<!-- ad:cap.fieldInfra --> и введите оба значения в долларах в месяц. Снижение или очистка не требуют кода; повышение требует одноразового кода. **Движок решений — модель · частота · кандидаты · свечи**<!-- ad:brain.heading --> показывает модель (по умолчанию `claude-opus-5`) и частоту вызова (по умолчанию каждые 24 часа).
- **Готовые профили — Осторожный · Сбалансированный · Рискованный**<!-- ad:preset.heading -->: в самом верху вкладки настроек. Один выбор сразу заполняет все настройки риска — доли риска, фьючерсы, лимит плеча, направление шорта и интервал тика. В новой установке ничего не выбрано, а выбор профиля требует одноразового кода. Профиль хранит проценты, а не суммы: панель при каждом открытии рассчитывает суммы в USDT из вашего свободного баланса USDT, и профиль, у которого одна позиция оказалась бы меньше минимальной суммы ордера Binance, не предлагается — его карточка объясняет почему. Поля фьючерсов заполняются, только если у вашего ключа есть разрешение на фьючерсы; шорт остаётся выключенным в каждом профиле. Месячный лимит расходов не входит в профиль. После выбора любую настройку по-прежнему можно изменить вручную; тогда профиль показывается как «свои значения». Кнопка **i** объясняет профили. Это программное обеспечение не является финансовой консультацией.
- **Доли риска — одна позиция · общая экспозиция**<!-- ad:caps.heading -->: в новой установке рождаются **пустыми**; числа вы вводите сами или выбираете готовый профиль — сама эта форма ничего не предлагает. Обе — процент от вашего **свободного баланса USDT на Binance** (USDT в вашем собственном спотовом кошельке, которые ещё не вложены в позицию): **Доля одной позиции**<!-- ad:prereq.names.single --> — наибольшая часть, которую может занять ОДНА новая позиция; **Общая экспозиция**<!-- ad:prereq.names.total --> — наибольшая часть, которую могут занять ВСЕ открытые позиции вместе; доля одной позиции не может быть больше общей. В **Настройки → Доли риска**<!-- ad:tabs.settings>caps.historyGroup --> сами введите каждое число в **Доля одной позиции (процент от вашего свободного баланса USDT)**<!-- ad:caps.singleLabel --> и **Общая экспозиция (процент от вашего свободного баланса USDT)**<!-- ad:caps.totalLabel -->, введите одноразовый код и нажмите **Сохранить доли риска**<!-- ad:caps.apply --> — каждое сохранение требует нового кода. Допустимо: число больше нуля, не более трёх знаков после запятой; пустое поле сохраняет своё значение. Сохранённые значения заново читаются с сервера; после этого две строки "Перед запуском"<!-- ad:engine.beforeYouStart --> показывают ✓. Изменение действует со следующего решения движка о входе; уже открытые позиции сохраняют свой размер.
- **Переключатель входов**<!-- ad:entry.heading -->: рождается **ВКЛ**<!-- ad:common.on --> — движок может открывать новые позиции по своему решению, как только всё остальное настроено. Нажмите переключатель, чтобы изменить его; при включении появляется "Прочитайте перед включением"<!-- ad:entry.readFirst --> с предупреждением из начала этой страницы и флажком, и оба направления требуют одноразового кода. В положении **ВЫКЛ**<!-- ad:common.off --> движок работает, выходы и защита продолжаются, но новые позиции не открываются и движок решений не вызывается.
- **Лимит плеча**<!-- ad:risk.fields.leverageCap --> и **Направление шорт**<!-- ad:risk.fields.shortMode -->: в новой установке лимит плеча **пуст**, а направление шорт — **Только лонг**<!-- ad:risk.modes.NONE.label -->. Пока лимит плеча пуст, путь фьючерсов закрыт: сделки с плечом не открываются, и программа никогда не выбирает число сама — готовый профиль заполняет его, только если вы выбрали этот профиль и у вашего ключа есть разрешение на фьючерсы. Кнопка **i** рядом с каждой строкой объясняет настройку. Чтобы изменить их, открой **Изменить эту настройку (нужен одноразовый код)**<!-- ad:risk.change -->; каждое изменение требует одноразового кода. Эта версия пока не планирует фьючерсных сделок сама: путь фьючерсных ордеров проверяется в тестовой сети Binance Futures (учебный счёт с тестовыми деньгами, отдельный от твоего настоящего). Использовать ли фьючерсы с реальными деньгами — твоё решение.

### 4. Капитал

Движок торгует **свободными USDT на вашем спотовом кошельке Binance**, поэтому ключу нужно **Enable Spot & Margin Trading**. Размер одной позиции — **Доля одной позиции**<!-- ad:prereq.names.single --> × свободный баланс USDT. Binance отклоняет ордер ниже минимальной стоимости ордера для пары (её фильтр NOTIONAL); движок читает этот минимум у Binance перед каждым ордером — на аккаунте автора он был **5 USDT** для большинства проверенных пар и 1 USDT для некоторых (измерено 2026-09-10). Если доля × свободный баланс меньше, позиция не открывается; движок продолжает работать и защищать. Панель не подключается к Binance, поэтому не может сравнить сегодняшний свободный баланс с этим минимумом: её строка **Капитал**<!-- ad:prereq.names.capital --> показывает последнюю измеренную стоимость счёта. Сколько вносить — решаете вы.

### 5. Запуск движка

Когда каждая строка "Перед запуском"<!-- ad:engine.beforeYouStart --> ✓, вкладка **Статус**<!-- ad:tabs.status --> показывает зелёную кнопку **ЗАПУСК**<!-- ad:engine.start -->. Нажмите её, введите код в "Одноразовый код (6 цифр) — код из приложения-аутентификатора"<!-- ad:engine.codeLabel --> и нажмите **Запустить движок**<!-- ad:engine.startEngine -->. Карточка покажет **Работает**<!-- ad:engine.state.RUNNING.name --> и "Запуск принят: движок может работать до …"<!-- ad:engine.started|upto:until --> — состояние заново читается с сервера, а не угадывается. Если интервал тиков не выбран, ответ будет "Движок не запустился: интервал тиков не выбран."<!-- ad:engine.notStartedTick|s1 --> и ничего не изменится. Осторожный порядок: сначала переведите **Переключатель входов**<!-- ad:entry.heading --> в **ВЫКЛ**<!-- ad:common.off -->, запустите движок и день наблюдайте **Работает**<!-- ad:engine.state.RUNNING.name -->, затем решите, включать ли входы.

### 6. Остановка движка

Пока движок работает, карточка показывает красную кнопку **СТОП**<!-- ad:engine.stop -->: выберите **Только остановить**<!-- ad:stop.modes.HOLD.title --> (новых позиций нет; открытые позиции и их защитные ордера на бирже остаются как есть) или **Остановить и запросить закрытие**<!-- ad:stop.modes.CLOSE_ALL.title --> (запрос на закрытие записывается; сегодня программа сама позиции не закрывает), введите **ключ остановки** из `stop-key.txt` (шаг установки 5 — не одноразовый код) и нажмите **Остановить движок**<!-- ad:stop.sendPanel -->. Если панель не открывается, **экран остановки** по адресу `/durdur` ("Winvestour · остановка движка"<!-- ad:stop.title -->) делает то же без сессии и кода: выберите под **Что должно произойти?**<!-- ad:stop.legend -->, введите ключ в **Ключ остановки**<!-- ad:stop.keyLabel --> и нажмите **Остановить**<!-- ad:stop.send -->. Ключ никогда не хранится в браузере.

![Экран остановки — mobile 390](images/stop-screen-mobile-390.png) ![Экран остановки — desktop 1280](images/stop-screen-desktop-1280.png)

### 7. **История**<!-- ad:tabs.history --> и **Тех. данные**<!-- ad:tabs.technical -->

**История**<!-- ad:tabs.history --> показывает последние позиции (вход, размер, комиссия, брутто и нетто) и каждое изменение настроек (кто, когда, старое → новое). **Тех. данные**<!-- ad:tabs.technical --> хранит все измеренные подробности, которые читает панель, — карточки движка, прогона и здоровья, строки позиций и откуда взято каждое число; эти серверные фразы тоже следуют языку панели.

На вкладке **Статус**<!-- ad:tabs.status --> раздел **Кратко**<!-- ad:status.summaryHeading --> показывает также фандинг, уплаченный и полученный в текущем периоде, в USDT, либо сообщает, что записей фандинга нет (у счёта без сделок с фьючерсами их нет). Причины остановок и пропущенных входов написаны понятными фразами на языке панели.

### 8. Чего нет в этом выпуске

Push-уведомления по умолчанию выключены: для них нужен ваш собственный проект Firebase — смотрите раздел «Необязательно: подключите собственный Firebase для push-уведомлений» ниже. Биометрическая блокировка есть (**Настройки → Биометрическая блокировка**<!-- ad:tabs.settings>lock.heading -->, по умолчанию выключена) и требует проверки отпечатка или лица на вашем устройстве. Приложения для Android нет; панель — это веб-страница, которую можно добавить на главный экран телефона. Запуск бота на своём компьютере не поддерживается (движок запускает Vercel Cron).

## Ежемесячная стоимость работы

Каждое число здесь взято из собственных измерений этой программы на развёртывании сопровождающего; ни одно не является оценкой. При непрерывной работе движка в дешёвом режиме, одной открытой позиции и одном вызове Мозга в день измеренная сумма составляет **≈ 9,60 – 9,90 $ в месяц** (Neon ≈ 5,30 $ · Vercel ≈ 1,50 $ верхняя граница · Upstash 0 $ в пределах бесплатной квоты · Anthropic ≈ 2,84 $). ## Обновление

Каждый из 4 шагов ниже проходится перед каждым выпуском на копии, установленной из версии 1.0.0 и содержащей данные в базе, — автоматической проверкой обновления. Шаг, который так не проходится, здесь не записан.

1. Получите новую версию в папку, из которой вы устанавливали. Если вы клонировали этот репозиторий через git, выполните в этой папке команду ниже; если вы скачивали ZIP, скачайте новый ZIP, распакуйте его в новую папку, скопируйте туда свой файл `.env` (если вы его создавали) и продолжайте там. Ваших значений нет в коде: git игнорирует файл `.env`, папка с резервными копиями находится вне репозитория, а значения, которые вы ввели в Vercel, остаются в Vercel:

```sh
git pull
```

Ожидаемый результат: команда завершается без конфликта и перечисляет изменённые файлы; поле `version` в `package.json` — номер новой версии; ваш файл `.env` на месте.

2. Установите зависимости новой версии:

```sh
npm ci
```

Ожидаемый результат: команда завершается без ошибки.

3. Примените изменения базы данных новой версии со своего компьютера при заданном `DIRECT_URL`, как в шаге установки 10. Применяются только те изменения, которых ещё нет в вашей базе данных, по порядку; таблицы не создаются заново, существующие строки сохраняются:

```sh
npx prisma migrate deploy
```

Ожидаемый результат: вывод заканчивается строкой `All migrations have been successfully applied.`, если новая версия приносит изменения базы данных, или сообщает `No pending migrations to apply.`, если не приносит. Ваши доли риска, настройки и история не меняются; обновление не запускает движок и ничего не включает. Если команда завершилась ошибкой, см. страницу вики Troubleshooting.

4. Разверните новую версию: отправьте обновлённую папку в свой репозиторий GitHub так же, как в шаге установки 13; Vercel соберёт её автоматически. Его скрипт `vercel-build` сначала отклоняет любую миграцию, которая удалила бы данные, затем снова выполняет ту же команду миграции (безвредно: ничего не ожидает) и собирает. Переменные окружения, которые вы ввели в Vercel, остаются как есть.

Ожидаемый результат: развёртывание достигает состояния **Ready**, а `https://<ваш-проект>.vercel.app/api/health` возвращает `{"ok":true,...}`. Панель показывает то же состояние движка, что и до обновления: остановленный движок остаётся остановленным. Если новой версии нужна переменная, которой нет в вашем развёртывании, сервер не запускается, а ошибка называет недостающую переменную.

## Необязательно: подключите собственный Firebase для push-уведомлений

Push-уведомления необязательны и **по умолчанию выключены**. В этой копии нет ни проекта Firebase, ни ключа Firebase, ни какого-либо значения Firebase: три переменные ниже рождаются пустыми, и пока они пусты, программа работает как обычно — панель сообщает **Уведомления выключены: Firebase не добавлен**, а каждая остановка или тревога по-прежнему записывается во вкладку «История». Чтобы включить их со своим проектом Firebase, выполните 4 шага ниже; каждый из них перед каждым выпуском проходится автоматической проверкой, которая использует созданный локально заменитель файла сервисного аккаунта Firebase и локальный заменитель Firebase (настоящий аккаунт Firebase не используется). Чтобы снова выключить уведомления, удалите три переменные и разверните проект заново. Эта программа не измеряет собственную стоимость Firebase; смотрите страницу цен Firebase.

1. В консоли Firebase создайте собственный проект (или откройте уже существующий), перейдите в **Project settings → Service accounts** и нажмите **Generate new private key**. Скачается файл JSON. Храните его вне папки репозитория и никогда не коммитьте: это секрет, как и ваш ключ Binance.

Ожидаемый результат: файл `.json`, среди полей которого есть `project_id`, `client_email` и `private_key`.

2. В Vercel откройте проект → **Settings → Environment Variables** и добавьте три переменные, скопировав каждую из поля этого файла JSON: `FIREBASE_PROJECT_ID` ← `project_id` · `FIREBASE_CLIENT_EMAIL` ← `client_email` · `FIREBASE_PRIVATE_KEY` ← `private_key`. Для `private_key` скопируйте значение целиком, включая первую и последнюю строки; последовательности `\n` можно оставить как есть. Задайте все три или ни одной: если задана только часть, уведомления остаются выключенными, а панель называет отсутствующую или неверную переменную (но никогда её значение).

Ожидаемый результат: три имени есть в списке; их значения нигде не показываются ни в панели, ни в журналах.

3. Разверните проект заново, чтобы новые переменные были прочитаны (Vercel → **Deployments** → последнее развёртывание → **Redeploy**).

Ожидаемый результат: в панели **Настройки → Уведомления** сообщает, что уведомления включены.

4. Уведомление доходит только до устройства, которое зарегистрировало свой токен Firebase Cloud Messaging в вашей установке: `POST /api/device` с сессией панели и телом `{"token": "<токен устройства>", "platform": "web"}` (или `"android"`). В этой копии нет приложения, которое сделает это за вас, — приложения для Android нет, — поэтому этот шаг для разработчика, который пишет собственный клиент с Firebase. Без зарегистрированного устройства ничего не отправляется, и запись об остановке или тревоге сообщает об этом.

Ожидаемый результат: конечная точка отвечает `{"ok":true,"devices":1,...}`; следующая остановка или тревога доставляется на это устройство, и её запись сообщает, что уведомление отправлено.

## Вопросы и устранение неполадок

### Развёртывание на Vercel падает с сообщением о cron-выражениях

Вы на тарифе Hobby. По документации Vercel cron-выражение, срабатывающее чаще раза в день, *падает при развёртывании*; расписание этой программы — каждую минуту, и в панели его не изменить. Перенесите проект в команду Pro или не запускайте его на Vercel Hobby.

### Сервер не запускается и печатает «ORTAM DEĞİŞKENİ SÖZLEŞMESİ İHLALİ — uygulama açılmıyor»

Переменная окружения отсутствует или некорректна (это серверное сообщение пока на турецком). Строки под ним называют каждую переменную и причину отказа (например, мастер-ключ не из 44 символов base64) — но никогда её значение. Сравните свои имена с `.env.example` и таблицей в разделе «Что понадобится».

### `/api/health` отвечает `{"ok":true,...}`, но панель просит пароль, а эндпоинты настроек отвечают 401 с `{"ok":false,"reason":"NO_SESSION"}`

Это ожидаемое состояние без сессии. Введите пароль владельца в поле **Пароль**<!-- ad:login.password --> панели и нажмите **Войти**<!-- ad:login.submit --> (см. «Первое использование»); та же страница откроет панель, перезагрузка не нужна.

### **ЗАПУСК**<!-- ad:engine.start --> не показывается, или движок сообщает "Движок не запустился: интервал тиков не выбран."<!-- ad:engine.notStartedTick|s1 -->

**ЗАПУСК**<!-- ad:engine.start --> появляется, только когда каждая строка "Перед запуском"<!-- ad:engine.beforeYouStart --> ✓. Следуйте ссылкам "Сначала: …"<!-- ad:prereq.keyFix|pre -->. Если интервал тиков пуст (он рождается пустым), выберите его в **Настройки → Интервал тиков**<!-- ad:tabs.settings>prereq.names.tick --> и запустите снова. В новой установке две доли риска рождаются пустыми: введите их в **Настройки → Доли риска**<!-- ad:tabs.settings>caps.historyGroup --> (см. «Первое использование», шаг 3).

### Мой ключ Binance отклоняется с **P1_WITHDRAWALS**, **P1_UNIVERSAL_TRANSFER** или **KEY_TYPE_NOT_ED25519**

Создайте на Binance новый API-ключ типа **Ed25519** с **отключёнными** выводом средств и универсальным переводом и добавьте его в панели. В панели отказ читается как "Ключ ОТКЛОНЁН: …"<!-- ad:key.withdrawals|pre --> и называет право, которое нужно выключить. Отклонённый ключ не сохраняется и не журналируется.

### Нужно ли ограничивать API-ключ Binance IP-адресом?

При обычной настройке Vercel — не фиксированным адресом: функции Vercel по умолчанию используют динамические исходящие IP-адреса, а фиксированные исходящие адреса — платная функция Vercel Static IPs (100 $ в месяц за проект, документация Vercel прочитана 2026-09-26). Без ограничения по IP действует собственное правило Binance (объявление Binance от 2021-07-26): право ключа **Enable Spot & Margin Trading** действует **90 дней** с момента активации и затем автоматически выключается — включите его снова на Binance, иначе движок не сможет размещать ордера. Binance также сообщала, что ключи без ограничения по IP, не используемые 30 дней, удаляются; панель показывает 30-дневный счётчик в **Настройки → API-ключ Binance → Технические подробности**<!-- ad:tabs.settings>key.heading>common.technicalDetails -->.

### Я потерял пароль, аутентификатор (TOTP) или ключ

- **Пароль или TOTP:** отложите старый `owner-credentials.txt`, снова выполните `npm run owner:credentials`, замените в Vercel `OWNER_PASSWORD_HASH`, `OWNER_TOTP_SECRET` и `SESSION_SECRET` тремя строками нового `vercel-env-owner.txt` и заново разверните. Все открытые сессии завершатся; добавьте новый ключ настройки TOTP в приложение-аутентификатор.
- **Ключ остановки:** отложите `stop-key.txt`, выполните `npm run stop:credential`, запишите новый хеш в `STOP_KEY_HASH` и заново разверните.
- **Потерян мастер-ключ** (`ENCRYPTION_MASTER_KEY`): сохранённый ключ Binance больше не расшифровать и не восстановить. Удалите этот API-ключ на Binance, отложите `encryption-master-key.txt`, выполните `npm run key:encryption-master`, запишите новое значение в `ENCRYPTION_MASTER_KEY`, заново разверните и добавьте в панели новый ключ Binance. Если старый мастер-ключ у вас ещё есть и вы лишь хотите его сменить, используйте вместо этого ротацию (шаг установки 15).
- **Потерян закрытый ключ Binance:** удалите этот API-ключ на Binance, отложите старые файлы `.pem`, выполните `npm run key:generate`, создайте новый API-ключ с новым открытым ключом и добавьте его в панели.

### Как удалить установку и перестать платить?

Сначала остановите движок (**СТОП**<!-- ad:engine.stop --> на вкладке **Статус**<!-- ad:tabs.status --> или `/durdur`). Затем:
- удалите API-ключ на Binance (Profile → API Management) — одно это прекращает любой торговый доступ;
- удалите проект Vercel (Project → Settings → Delete Project) — это убирает запланированную задачу, работающую каждую минуту; если этот проект был единственной причиной для Vercel Pro, измените или отмените тариф в настройках оплаты Vercel;
- удалите проект Neon и базу данных Upstash в их собственных консолях;
- отзовите API-ключ Anthropic.

Файлы в `winvestour-backup` относятся только к этой установке; удалите их, когда они больше не нужны.

### Binance отвечает 451 «Service unavailable from a restricted location»

Binance блокирует запросы из США. Поэтому `vercel.json` закрепляет функции в регионе `hnd1` (Токио); если сменить регион на американский, каждый вызов Binance падает с 451, и движок сообщает, что регион заблокирован.

### Отправляет ли эта программа что-нибудь своему автору?

Нет. Она обращается только к Binance (с вашим ключом), к вашим собственным Neon и Upstash и к Anthropic (с вашим ключом). Единственный сторонний трафик, который она не контролирует, — телеметрия сборки Next.js, описанная в разделе о стоимости; её можно отключить через `NEXT_TELEMETRY_DISABLED=1`. Только если вы подключите необязательное дополнение Firebase, она также обращается к конечным точкам входа Google (OAuth) и Firebase Cloud Messaging с вашим собственным сервисным аккаунтом.

### `npx prisma migrate deploy` завершается ошибкой во время обновления

Если в выводе написано `Error: Connection url is empty.`, в этом терминале не задана `DIRECT_URL`: поместите прямую (без пула) строку подключения Neon в файл `.env` рядом с `package.json` (как в шаге установки 10) или задайте её в терминале и выполните команду снова — в базе данных ничего не изменилось. При любом другом сообщении: не редактируйте и не удаляйте файлы в `prisma/migrations` и не меняйте таблицы вручную; выполните `npx prisma migrate status`, чтобы увидеть, какое изменение ещё не применено, и спросите в GitHub **Discussions → Q&A** (никогда не вставляйте строку подключения).
